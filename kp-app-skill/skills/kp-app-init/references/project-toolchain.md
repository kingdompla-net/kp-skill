# KP 앱 기준 도구 모음과 버전 기록

이 문서는 `kp-app-init`이 React 앱의 도구를 고를 때 참고하는 기준입니다. 도구 종류와 역할은 아래 구성을 따르고, 버전은 대상 프로젝트의 호환성에 맞춰 정합니다. 이 문서의 예시 버전을 대상 프로젝트에 그대로 복사하지 않습니다.

## 기준 도구

| 영역            | 도구                                                 | 기준 역할                                                                                                                                           |
| --------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 런타임          | Node.js                                              | 프로젝트의 `.nvmrc`, `.node-version`, `.tool-versions`, `engines.node`, CI 설정을 확인하고 실제 요구 버전을 기록합니다.                             |
| 패키지 관리자   | 대상 저장소가 이미 사용하는 npm, pnpm, yarn 또는 bun | 기존 lockfile과 package manager 설정을 유지합니다. 다른 패키지 관리자로 임의 전환하지 않습니다.                                                     |
| UI              | React, React DOM                                     | 화면 렌더링과 컴포넌트를 구성합니다.                                                                                                                |
| 언어            | TypeScript                                           | 앱의 정적 타입을 정의합니다.                                                                                                                        |
| 라우팅          | React Router DOM                                     | 브라우저 경로와 화면을 연결합니다. 대상 소스가 이미 다른 router를 쓰면 교체 전에 사용자에게 확인합니다.                                             |
| 서버 상태       | TanStack React Query                                 | API query·mutation 및 서버 상태를 관리합니다.                                                                                                       |
| 클라이언트 상태 | Zustand                                              | 서버 응답을 복제하지 않는 UI 전역 상태를 관리합니다.                                                                                                |
| 응답 검증       | Zod                                                  | 외부 API 응답을 런타임에서 검증합니다.                                                                                                              |
| 스타일          | Tailwind CSS                                         | 기존 디자인을 보존하면서 유틸리티 스타일과 토큰을 구성합니다.                                                                                       |
| 빌드            | Vite, `@vitejs/plugin-react`                         | 개발 서버와 React 앱 빌드를 구성합니다.                                                                                                             |
| 정적 검사       | Biome, ESLint                                        | 각각 맡는 lint·import 정리 규칙을 명확히 설정합니다. 겹치는 규칙은 중복 실행하지 않습니다.                                                          |
| 서식            | Prettier                                             | 대상 저장소의 format/check 명령과 호환되게 서식을 검사·정리합니다. Biome formatter로 대체하려면 설정과 기존 명령을 함께 이전하고 결과를 확인합니다. |
| UI primitive    | Radix UI                                             | 화면 설계에서 대화상자 등 접근성 primitive가 필요한 경우 사용합니다. 사용하지 않는 primitive는 추가하지 않습니다.                                   |

대상 소스가 이미 동작하는 React·router·build 체계를 사용하면 이를 조사하고 사용자 화면을 보존합니다. 이 기준과 다른 핵심 도구가 있거나 교체가 필요하면 차이와 영향 범위를 먼저 설명하고 확인받습니다. 보조 도구는 실제 코드나 검증 절차에서 쓰임이 확인될 때만 추가합니다.

## 버전 기록 원칙

- 도구 버전은 대상 `package.json` 선언과 해당 lockfile의 해결 버전을 각각 확인해 기록합니다. 예를 들어 `^19.2.0`은 허용 범위이고 lockfile의 `19.3.1`은 실제 재현 설치 버전입니다. lockfile 버전이 선언 범위에 포함되고 manifest의 루트 명세와 맞으면 두 값이 달라도 정상입니다.
- lockfile이 없거나 manifest와 맞지 않으면 패키지 관리자를 확인해 대상 저장소 방식으로 생성·갱신하고 차이를 검증합니다. 사용자 작업을 덮어쓸 수 있는 lockfile 삭제·광범위 재생성은 하지 않습니다.
- Node.js는 package version의 `@types/node`와 구분해 기록합니다. `@types/node` 버전은 Node.js 실행 버전을 정하지 않습니다.
- Node.js 버전이 프로젝트 설정에 고정되어 있지 않으면 에이전트 머신의 현재 버전을 프로젝트 기준으로 기록하지 않습니다. 대상 프레임워크와 도구가 지원하는 범위를 확인하고 사용자에게 프로젝트 버전 고정 여부를 묻습니다. 고정하지 않기로 하면 명세에 `미고정`이라고 기록합니다.
- 명세에는 실제 build·lint·format·test 명령과 테스트 도구 유무를 기록합니다. `npx <도구>@latest`처럼 lockfile의 버전을 우회하는 명령이 있으면 별도 표기하고, 재현성이 필요하면 설치 버전을 사용하는 명령으로 바꾸도록 사용자와 조정합니다.
- Firebase CLI처럼 전역 설치된 도구는 프로젝트 의존성 버전과 구분합니다. 확인된 경우 관찰한 버전을 적고, 저장소에서 고정하지 않았다는 사실도 함께 밝힙니다.

## 프로젝트 명세 생성

초기화 완료 시 [프로젝트 도구 명세 템플릿](../assets/templates/.agents/references/spec.md)을 대상 저장소의 `.agents/references/spec.md`로 복사한 뒤 실제 값으로 채웁니다. 명세에서 확인된 값만 기준으로 삼고, 루트 `AGENTS.md`가 이 파일을 모든 작업자의 필수 참고 문서로 라우팅하게 합니다.
